Что ещё из OpenAI API может пригодиться OpenCode?

Какие возможности OpenAI-совместимого API могут быть полезны в интеграции Tropass с OpenCode.

Исследование показало: прямой API может дать OpenCode три полезных сценария.

Наиболее интересны голосовой ввод до запуска агента и сжатие длинной сессии в OpenCode V2. Озвучивание результата — дополнительная возможность. Это кандидаты для проверки, а не утверждение, что достаточно опубликовать новые ручки: каждому сценарию нужна интеграция на стороне OpenCode.

Почему стоит проверить Responses и сжатие V2

OpenCode V2 перечисляет отдельный провайдер @opencode/ai/providers/openai-compatible/responses. В настройках сжатия есть режим native; для Responses OpenCode применяет потоковое сжатие, если маршрут его поддерживает, либо отдельный endpoint там, где доступен только он. Поддержка зависит от конкретного маршрута, развёртывания и модели — одно название пакета её не гарантирует. Документация V2 по сжатию.

По контракту OpenAI, результат сжатия — не обычное текстовое резюме, а новый контекст с непрозрачным checkpoint. Его нужно передать в следующий POST /v1/responses. Поэтому адаптер, который просто переименует chat/completions в responses или вернёт текстовое summary из /responses/compact, не докажет совместимость.

Минимальный эксперимент: настроить Responses-маршрут Tropass в V2, пройти обычный цикл с tool calls, запустить ручное сжатие и продолжить сессию. Зафиксировать фактические запросы OpenCode: вызывает ли он /responses/compact или передаёт context_management в потоковом /responses, и воспроизводится ли checkpoint после следующего шага. До такой проверки это кандидат, а не обещанная возможность.

Когда прямой API полезнее MCP

Для голосового ввода и озвучивания вызов делает клиентский код до или после работы агента; OpenAI-совместимая ручка позволяет использовать сервис через обычный SDK и в OpenCode, и в других клиентах. Действия, которые агент выбирает сам во время работы, уже доступны ему через MCP.
